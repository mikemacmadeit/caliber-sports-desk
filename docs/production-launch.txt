COMPLETED LOCALLY
1. Account protection: shared atomic login/recovery limits, signed proxy identity,
   expiring single-use recovery and verification tokens, session revocation, email
   verification before checkout, and password-confirmed account removal. Accounts
   with a renewing subscription must cancel through billing before removal.
2. Billing: duplicate-event receipts, account locking, older-event protection,
   protection against an old subscription canceling its replacement, repeated
   checkout idempotency, active-subscription checks, finite request timeouts.
3. Boards: API is the source of picks/results. Removed frontend ESPN grading and
   static JSON fallback paths. Private responses use no-store. Empty/error results
   no longer resurrect old local boards or a previous customer's cached response.
4. Record: prospective picks remain separate from unverified archives/replays.
   Main and named alternate results are read from recorded game data. Official
   statistics wait for final games; provisional live TD markers can still appear.
   Missing participation evidence is unresolved, not an invented TD loss. Returns
   require actual eligible recorded prices. Corrections append an audit entry and
   preserve the original published result. Recent published boxes are rechecked.
5. Workers: TD model/simulation refresh runs in the scheduled odds lane. Public
   production TD reads never launch model/data workers. Optional paid college injury
   coverage cannot fail otherwise successful free-source ingestion. Source failures
   and unknown coverage remain explicit. Interrupted jobs are detected under the
   lane lock. Downloads have bounded retries and atomic replacement. NFL play data
   reads use the required columns and avoid materializing duplicate row lists.
6. Operations: versioned Alembic migrations, production startup schema validation,
   limited PostgreSQL connection pools, database health check and feed readiness
   probe, CI with PostgreSQL and frontend builds, pinned Python dependencies,
   patched npm dependency override and a restricted Docker build context.
7. Customer UI: recovery, verification, deletion, errors, keyboard skip link, help,
   support-contact configuration, and clearly marked privacy/terms drafts.
   TD card payload omits internal matrices and keeps the existing user explanations.

VALIDATION
The final Python run passed 704 tests, including six real PostgreSQL tests. The
frontend production build and Docker build passed. The suite reported 11 existing
empty-data/deprecation warnings, with no failures. Logs are in the evidence folder.
Runtime API checks covered signup, secure cookies, verification reuse, password
reset/session revocation, test-account deletion and rate-limit enforcement.
Anonymous -> subscriber -> anonymous reads proved the synthetic private picks and
alternate did not leak between viewers. No production users were involved.

Fresh PostgreSQL migrations matched the model's tables/columns. A local pg_dump /
pg_restore rehearsal matched all 70 tables' row counts and data hashes.
npm audit reported zero vulnerabilities at the time of checking; pip check passed.
The saved 12-game payload fell from 1,615,979 to 422,429 bytes (73.9% smaller).
This is a serialization comparison, not a measured production latency improvement.

returned 503 because the disposable test database had never run ingestion jobs.
