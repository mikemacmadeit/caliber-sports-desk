Release candidate: production readiness corrections, November 16, 2026

This supersedes implementation details in the preceding local readiness notes.
Deployment success must be verified separately using the exact released commit.

Behavior
- ATS pages preserve the server's selection, subscription lock and final result.
- TD participation-unconfirmed results stay pending; confirmed inactivity is void.
  Live scoring highlights do not count as settled wins. Passing TDs are excluded.
- Daily, monthly and yearly records use the corrected database ledger. Historical
  display archives without proven pregame capture are excluded from verified returns.
- Worker-produced college evidence is compressed, hashed and shared in PostgreSQL.
  Consumers preserve source timestamps. PostgreSQL and SQLite use the same exporter.
  Missing raw historical plays cannot erase existing measured evidence.
- Nested provider failures mark jobs degraded, retain previous shared inputs and
  appear in readiness. Shared college artifact freshness is checked separately.
- TD refreshes commit progress after each game and reuse recent completed work.
  Supervisor timeouts release locks; a later run resumes remaining work.
- Scenario Lab starts with saved pregame probabilities and actual team expectations.
  Team-scoring overrides have an explicit mathematical effect. Unsupported wind
  controls were removed. Draw counts, concurrency and per-account requests are bounded.
- All current TD selections and scenarios remain experimental. This release does
  not promote a failed model artifact or claim an accuracy improvement.

Boundaries
Original picks and historical outcomes must not be replaced with hindsight picks.
Missing source data must not be labeled healthy. Known-out players are withheld,
but a fresh active report cannot guarantee future snaps or a touchdown.
SMTP, live Stripe configuration, owner policies and domain setup remain owner tasks.
Full browser journey sign-off requires the project's IronBee tools, unavailable
in the current agent session. No equivalent browser sign-off is claimed.
The full selection/simulation policy still needs prospective NFL and college
evaluation separately, using frozen pre-kickoff candidates, inputs and prices.

Optimization and reliability follow-up (November 16)
- A full NFL refresh reproduced a 512 MB OOM hidden by earlier warm/not_due checks.
  Project only needed fields, decode without parallel column buffers, filter dated
  depth charts in bounded batches and load game context in small groups. Reuse
  player/roster identity lookups instead of querying once per historical row.
- The input lane retains its advisory lock in a lean parent and runs each provider
  stage in a separate child process. The existing supervisor deadline/termination
  owns all descendants. Provider failures remain visible and other feeds still run.
- Commit completed NFL source stages independently; share game-flow JSON without
  materializing several full copies. College refreshes discard superseded/current
  temporary frames and use narrow, streamed identity queries.
- Grade saved TD primary/alternate cards using batched official and fallback stats.
  A restored 12-game board required 2 queries instead of 37, with identical output.
- Validate real calendar dates, months, leagues and parlay inputs. Reject duplicate
  parlay players, unsupported markets/sides/lines, and invalid/non-finite prices.
- ATS, schedule, ticket and prop failures are explicit. Tickets have a retry and
  bounded timeout; canceled filter requests cannot replace a newer card. Scenario
  inputs reset when changing dates, and copy accurately describes team-score edits.
- Subscription checks are reused only within one request. Database failure during
  access checks returns retryable 503 instead of telling a member to subscribe.
